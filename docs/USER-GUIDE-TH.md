# FLO · Hotel Operations — Pilot 1.0

ระบบจัดการงานโรงแรมที่พัฒนาต่อยอดแนวคิดจาก FLO เดิม โดยสร้างฐานข้อมูลใหม่ ไม่เชื่อม Firebase หรือแก้ ZIP ต้นฉบับ

## เริ่มใช้งาน
1. เปิด URL ของระบบ และเข้าสู่ระบบด้วยบัญชี ChatGPT ของเจ้าของเว็บไซต์
2. บัญชีแรกจะได้รับบทบาทผู้จัดการอัตโนมัติ เว็บไซต์เริ่มเป็นส่วนตัวสำหรับเจ้าของเท่านั้น ต้องให้เจ้าของเปิดระบบครั้งแรกก่อนอนุญาตบุคคลอื่น
3. เพิ่มห้องจริงในบอร์ดห้อง สถานะการเข้าพักไม่ได้เชื่อม PMS
4. เปิดงานด้วยชื่อ ห้อง แผนก เวลาเป้าหมาย และรายการตรวจ (ถ้ามี)
5. รับงาน → เริ่มทำ → ตรวจรายการให้ครบ → เสร็จรอตรวจ → ผู้มีสิทธิ์ปิดงาน
6. ใช้หน้าส่งต่อกะเพื่อดูงานค้างและดาวน์โหลดข้อความสรุป ก่อนส่งกะให้บันทึกสิ่งที่ต้องทำต่อในข้อความประจำงาน
7. ส่งออกรายงาน CSV และสำเนาข้อมูล JSON ได้ที่หน้ารายงาน (สำเนา JSON ไม่รวมไฟล์รูป)

## สิทธิ์
- ผู้จัดการ: เห็นทุกแผนก จัดการทีม ห้อง และงาน
- FO: เห็นทุกแผนก เปิดงาน มอบหมาย ตรวจและปิดงาน
- Supervisor: เห็นและจัดการเฉพาะแผนกตนเอง; หัวหน้า HK ปรับสถานะห้องได้
- พนักงาน: เห็นงานแผนกตนเอง รับงานที่ยังไม่มีผู้รับ ทำงานที่ตนรับผิดชอบ และสื่อสารในงาน
- ผู้ใช้ที่ไม่มีบัญชีหรือถูกปิดใช้งาน เข้าอ่าน/เขียนข้อมูลผ่าน API ไม่ได้

บัญชีทีมงานในแอปกับสิทธิ์เข้าชมเว็บไซต์เป็นคนละส่วน การเพิ่มอีเมลในแอปยังไม่เชิญพนักงานหรือขยายสิทธิ์เว็บไซต์ ต้องตั้งค่าผู้ชมเว็บไซต์ให้เหมาะสมก่อนทดลองหลายคน ระบบรุ่นนี้ยังใช้การเข้าสู่ระบบผ่าน ChatGPT ไม่ใช่รหัสพนักงานสี่หลัก

## พฤติกรรมสำคัญ
- งานเก็บรายการเดิมตลอดวงจร ไม่ลบเมื่อปิด
- งานมี version ป้องกันการแก้ทับข้อมูลที่เปลี่ยนแล้ว
- รหัสงานสร้างก่อนส่ง หากคำขอเดิมถูกส่งซ้ำจะไม่สร้างงานซ้ำ
- การเปลี่ยนสถานะงานและประวัติทำในธุรกรรมเดียวกัน
- งานหลักปิดไม่ได้ถ้ายังมีงานย่อยที่ไม่จบ
- พักงาน ยกเลิก ส่งกลับ และเปิดซ้ำ ต้องให้เหตุผล
- เวลาบริการยังนับต่อระหว่างพักงาน ไม่หยุดนาฬิกาเพื่อทำให้รายงานดูดี
- รายการตรวจต้องครบก่อนส่งตรวจ
- รูปจัดเก็บใน R2 และตรวจสิทธิ์ก่อนเรียกดู รองรับ JPEG/PNG/WebP ไม่เกิน 2 MB ต่อรูป
- รีเฟรชข้อมูลอัตโนมัติทุก 15 วินาที ไม่ใช่ WebSocket
- ข้อมูลใช้เวลาประเทศไทยในการแสดงผล

## ข้อจำกัดก่อนใช้งานจริงเต็มโรงแรม
รุ่นนี้เป็น pilot สำหรับทดสอบขั้นตอนงาน ยังไม่มี Push เบื้องหลัง, การส่งต่อผู้บริหารอัตโนมัติ, งานตามตาราง, PMS, การจัดเวร, การทำงานออฟไลน์พร้อมคิวส่ง, การแจ้งเตือนเหตุฉุกเฉิน, การนำเข้า ZIP เดิม หรือการกู้คืนข้อมูลจาก JSON ผ่านหน้าจอ ต้องใช้อินเทอร์เน็ตในการบันทึก หากผิดพลาดแบบฟอร์มยังคงข้อความให้ลองส่งใหม่

หน้าเกินเวลาเป็นข้อมูลติดตาม ไม่ควรใช้แทนช่องทางฉุกเฉินของโรงแรม และเวลาในงานมาตรฐานเป็นค่าเริ่มต้นสำหรับทดลอง ผู้จัดการควรกำหนดเป้าหมายจริงตามกำลังคน

งาน/ผู้ใช้ในฐานทดสอบภายในไม่ถูกนำไปฐานเผยแพร่ ระบบเผยแพร่เริ่มว่าง ไม่มีชื่อแขกหรือข้อมูลโรงแรมจริง

ก่อนขยายทีม ให้ทดสอบเปลี่ยนกะ เน็ตขาด เครื่องไม่แจ้งเตือน งานหลายแผนก และการส่งกลับงาน รวมถึงยืนยันแผนสำรองข้อมูลและการเก็บรักษารูปตามนโยบายโรงแรม

## ลำดับพัฒนาถัดไป
1. ทดลองกับหัวหน้าแผนกและปรับมาตรฐานเวลา/อำนาจปิดงาน
2. กำหนดเวรและพื้นที่รับผิดชอบ พร้อมการยกระดับงานบนเซิร์ฟเวอร์
3. Push บนอุปกรณ์จริง พร้อมตรวจการรับงานและการส่งซ้ำ
4. งานตามตาราง เช็กลิสต์มาตรฐาน และประวัติอุปกรณ์
5. เชื่อม PMS หลังยืนยันผู้ให้บริการและวิธีเข้าถึงข้อมูล


## Pilot 1.1
- พนักงานเริ่มที่งานของฉัน เมนูเหลือ งานของฉัน / งานแผนก / ส่งต่อกะ เลขห้องใหญ่ขึ้น
- ล็อกรายการตรวจหลังส่งตรวจ ตรวจครบอีกครั้งก่อนปิด
- ฐานข้อมูลป้องกันงานหลักปิด/ยกเลิกทั้งที่งานย่อยยังเปิด และห้ามเพิ่มงานย่อยหลังปิด
- พักงานต้องระบุเวลาติดตามในอนาคต
- ส่งต่อกะเลือกผู้รับได้ ผู้รับเดิมรับผิดชอบจนคนใหม่ยืนยัน บันทึกเวลาและผู้รับจริง
- รายละเอียดงานโหลดประวัติของงานนั้นครบ โดยไม่ขึ้นกับ 1,500 รายการล่าสุดของภาพรวม
- ยังไม่มี Push เบื้องหลัง การจัดเวรอัตโนมัติหรือ PMS; JSON จากหน้ารายงานเป็นภาพข้อมูลหน้าจอ ไม่ใช่สำรองครบทั้งระบบ

## Pilot 1.2 — บอร์ด 320 ห้อง
- ห้องที่เลขขึ้นต้น 1 → ตึก A, 2 → ตึก B, 3 → ตึก C; ไม่อนุมานเลขชั้นจากเลขห้อง
- ดูช่องห้องขนาดเล็กหรือตาราง ค้นหาเลขห้อง กรองตึก โซน ความสะอาด ปิดซ่อม หรือมีงานค้าง
- ค่าเริ่มต้น 80 ห้องต่อหน้า เปลี่ยนเป็น 40 หรือทั้งหมดได้
- สีแสดงความสะอาดพร้อมข้อความ ป้ายปิดซ่อมแยกจากความสะอาด จำนวนบนมุมคือจำนวนงานค้าง
- คลิกห้องเพื่อดูรายละเอียดและเปิดงานค้างของห้องนั้นได้
- เพิ่มห้องเป็นชุด: วางเลขห้องบรรทัดละห้อง หรือ 2 คอลัมน์จาก Excel (เลขห้อง, ชั้น/โซน) โดยไม่ใส่หัวตาราง
- ตรวจรูปแบบและรายการซ้ำก่อนเพิ่ม ข้ามห้องที่มีอยู่แล้วโดยไม่เขียนทับสถานะ
- ห้องใหม่เริ่ม “ยังไม่ตรวจ / ยังไม่ยืนยัน” ไม่สร้างสถานะพร้อมใช้โดยอัตโนมัติ
- โซนเป็นข้อความที่โรงแรมกำหนดได้ เลขห้องเดิมที่ไม่ขึ้นต้น 1–3 จะแยกกลุ่ม “เลขเดิม / อื่น ๆ”
- เป้าหมาย 320 ห้องเป็นตัวเลขอ้างอิง ไม่สร้างเลขห้องขึ้นเอง ไม่บังคับว่าห้องที่ลงทะเบียนแล้วต้องมีครบ 320 ทันที
- ชุดห้องในภาพทดสอบเป็นข้อมูลจำลองเฉพาะเครื่อง ไม่ถูกนำขึ้นเว็บไซต์จริง
